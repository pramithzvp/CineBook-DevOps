Scope: a complete interactive frontend demonstration.

Login, registration, profile and hosted bookings are demo experiences. No real user authentication, payment, email or cinema reservation is performed. The existing Spring Boot + MySQL booking source is included separately and has not been run or integration-tested here.

2. Try the demo account

Open Log in → Try the demo account. No credential entry is required for this shortcut.

Email:    demo@cinebook.lk
Password: CineBook123!

The password form also accepts the sample credentials. Registration accepts a name, email and test password. Passwords need at least eight characters, uppercase and lowercase letters, and a number. Confirmation must match.

Use sample details only. Registered accounts and passwords exist only in JavaScript memory until refresh; they are never sent to an authentication server or written to local/session storage. Profile login is only a UI simulation and is not an access-control boundary. All bookings in this browser tab remain visible regardless of the demo profile.

Login එක බලන්න “Try the demo account” click කරන්න. සැබෑ password එකක් මෙයට දාන්න එපා. අලුතින් හදන demo account එක refresh කළාම නැති වෙනවා.

3. Complete booking walkthrough

  1. Select a cinema and an upcoming date.
  2. Choose a film’s showtime. You may open movie details first.
  3. Select seats, or choose “2 seats together” and press “Find seats”. Click selected seats again to remove them.
  4. Continue to contact details. A demo profile pre-fills the name and email; guests can fill them manually.
  5. Review the movie, date, time, cinema, seats and exact price. Edit the contact or return to seats if necessary.
  6. Confirm the demo booking. No charge is made. Save the ticket or download a calendar event.
  7. Open My bookings to find the reservation. Cancelling an upcoming demo booking releases its seats in this tab.

4. Open and run in VS Code

Download the new ZIP from this version and extract it to a new folder. The old ZIP from version 1 does not contain these changes. Open the extracted cinebook folder containing package.json in VS Code.

අලුත් ZIP එක extract කරලා VS Code → File → Open Folder තුළින් “cinebook” folder එක open කරන්න. පරණ project එකේ files උඩින් අහම්බෙන් overwrite නොකර අලුත් folder එකක් භාවිත කරන්න.

Requires Node.js 22.13 or later and pnpm. In Terminal → New Terminal:

node -v
pnpm -v
pnpm install
pnpm dev

If pnpm is missing and Corepack is available, run corepack enable first. Open the local address printed by the terminal. Keep the terminal running; press Ctrl+C to stop the server.

The frontend runs in demo mode with an empty NEXT_PUBLIC_API_BASE. MySQL and Java are not needed for frontend demo mode.

Useful commands

pnpm exec tsc --noEmit
node scripts/check-frontend.mjs
pnpm build
python3 scripts/export-source.py

The last command rebuilds the downloadable source ZIP after you edit the project.

6. Data and refresh behaviour

StateStored where?After refresh?
Theme, saved film IDs, preferred cinemaDevice-local localStorageRetained when storage is available.
Reservation history and cancellation stateTab-local sessionStorageRetained in this tab; closing the tab may clear it.
Demo account credentials and current profileIn-memory React stateReset; no password is persisted.
Unconfirmed seat selectionDialog stateReset. Selecting seats does not reserve them.

If storage is blocked, the frontend displays a notice and continues in memory. This is a device-local demonstration, not a multi-user reservation service. Seat changes in different tabs or devices are not synchronized in demo mode.

7. Backend connection boundary

The existing Spring Boot/MySQL code is retained. To use its booking availability and creation endpoints, run the backend separately and add a root .env.local:

NEXT_PUBLIC_API_BASE=http://localhost:8080

Restart the frontend after changing this setting. For a separately hosted API use its HTTPS origin and configure the backend’s FRONTEND_ORIGIN to the actual frontend origin. The hosted JavaScript preview cannot run Java or a local MySQL server.

The API adapter uses GET /api/availability and POST /api/bookings. Server-backed bookings do not display local cancellation controls because the supplied API does not support cancellation. Server-side account registration, authentication, account-specific booking retrieval, profile updates, payment and email endpoints must be added before production use. Do not treat the frontend demo profile or owner field as trusted identity.

Backend verification: the Spring Boot/MySQL implementation was not run here. It contains tests, but requires Maven and a database environment for verification.

8. Verification and practical limits

The frontend has focused checks for stable film/hall mapping, combined filters, price sorting, adjacent seats staying on one side of the aisle, full-hall behaviour, Sri Lanka time cutoffs, cancellation releasing seats, cinema isolation, malformed stored data, password rules and cancelled ticket labels.

Browser verification covers dark/light switching, the watchlist, movie filters/details, one-click demo login, seat selection, the booking review/receipt, cancellation and history. Browser print/PDF and calendar import ultimately depend on the user’s browser and calendar application. These controls create local files or print dialogs; they do not send invitations.

Layouts adapt to mobile and desktop, with larger type for primary controls, focus indicators, keyboard-accessible primitives and reduced-motion support. The sample catalogue contains three films. Programme, venues and film availability are demonstration data.
